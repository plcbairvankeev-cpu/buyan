# БУЯН — единый проект

Сообщество-центр «Буян» и его направления в одном проекте.

## Структура

```
buyan/
  index.html            ← Хаб-лендинг сообщества «Буян» (Дело · Медиа · Добро)
  vhod.html             ← Вход / регистрация участников (Supabase)
  kabinet.html          ← Личный кабинет участника (закрытая зона, 4 раздела)
  assets/app.css        ← стиль закрытой зоны
  assets/auth.js        ← логика входа (Supabase + демо-режим)
  assets/supabase-config.js  ← сюда вставить URL и anon-ключ Supabase
  README.md
  oborudovanie/         ← Направление «Промышленное оборудование» (полный сайт-каталог)
    index.html          Главная каталога
    production.html, batteries.html, solar.html, ev.html, home-energy.html
    tenders.html, about.html, contacts.html, cn.html, privacy.html, consent.html
    assets/css/styles.css
    assets/js/config.js  ← реквизиты, контакты, факты каталога
    assets/js/main.js    ← + плашка «◀ Сообщество Буян» (возврат в хаб)
```

## Как связаны

- **Хаб → каталог:** карточки «Промышленное оборудование» и «Энергетика» открывают `oborudovanie/…`.
  Пути заданы в `index.html` → блок `SITE_CONFIG.links` (легко поменять при хостинге).
- **Каталог → хаб:** вверху каждой страницы каталога — плашка «◀ Сообщество Буян» (ссылка `../index.html`).
  Она вставляется скриптом `oborudovanie/assets/js/main.js`; в отдельном сайте prom-site её нет.

## Открыть / развернуть

- Локально: двойной клик по `index.html` — переходы между хабом и каталогом работают по относительным ссылкам.
- На хостинге: залить папку `buyan/` целиком; хаб — корень, каталог — по адресу `/oborudovanie/`.

## Что заполнить

- Хаб: `SITE_CONFIG` внизу `index.html` — соцсети, цифры импакта, суммы, кейсы студии.
- Каталог: `oborudovanie/assets/js/config.js` — название ООО, реквизиты, контакты; PDF-файлы каталога.
- Отдельный сайт оборудования для партнёров (без брендинга «Буян») остаётся в `~/Claude/prom-site`.

## Вход участников (Supabase)

Файлы: `vhod.html` (вход/регистрация), `kabinet.html` (личный кабинет), `assets/app.css`,
`assets/auth.js`, `assets/supabase-config.js`. В хабе есть пункт меню **«Вход»**.

**Демо-режим (по умолчанию):** пока Supabase не настроен, `vhod.html` показывает «Войти в демо-режиме» —
можно посмотреть кабинет без реального входа (сессия хранится в localStorage браузера).

**Подключить настоящий вход:**
1. Создайте проект на [supabase.com](https://supabase.com). В **Project Settings → API** скопируйте
   `Project URL` и `anon public` ключ, вставьте в `assets/supabase-config.js`.
   `anon`-ключ публичный — держать во фронтенде штатно; `service_role` НЕ вставлять.
2. **Authentication → Providers → Email** включить. Подтверждение почты — по желанию.
3. Залейте сайт на хостинг (Supabase-вход требует интернет; двойной клик по файлу для реального входа не подойдёт).

**Важно — защита данных = RLS, а не редирект.** Редирект `kabinet.html` — это UX. Реальную защиту дают
политики Row Level Security в Supabase. Рекомендуемые таблицы (создать в SQL-редакторе):
`profiles` (участник, статус), `materials` (закрытые материалы), `events` + `event_signups`
(события и заявки), `deals` (сделки/проекты). На каждую включить RLS и политику вида
«читать может только авторизованный участник» (`auth.role() = 'authenticated'` или проверка `profiles.approved`).
Разделы кабинета сейчас — заглушки; подставьте выборку из этих таблиц.

**«Круг своих» (модерация входа):** открытая регистрация → добавьте флаг `approved` в `profiles`
и пускайте в закрытые разделы только одобренных (через RLS). Либо вход только по приглашению
(Supabase → Auth → отключить самостоятельную регистрацию, заводить участников вручную).
